# 객체지향 vs 절차지향 프로그래밍 비교

동일한 요구사항을 객체지향 프로그래밍(OOP) 스타일과 절차지향 프로그래밍 스타일로 각각 구현하여 두 패러다임의 차이점을 비교하고 학습하는 프로젝트입니다.

## 목적

-   데이터와 로직이 분리된 절차지향 코드의 특징을 이해합니다.
-   데이터와 로직을 하나의 단위로 묶는 객체지향의 캡슐화(Encapsulation)를 이해합니다.
-   요구사항 변경 시 각기 다른 두 스타일의 코드가 어떻게 변화에 대응하는지 비교 분석합니다.
-   객체지향 설계의 장점(유연성, 확장성, 유지보수성)을 코드를 통해 체감합니다.

## 기술 스택

*   **Language**: Java
*   **Testing**: JUnit 5

## 핵심 비교 포인트

아마도 이 프로젝트 내에는 같은 문제를 푸는 두 가지 방식의 코드가 존재할 것입니다.

1.  **절차지향 방식**: 데이터(Data)를 담는 객체와, 이 데이터를 받아 처리하는 로직(Procedure)이 담긴 서비스 클래스가 분리되어 있는 구조일 가능성이 높습니다.
2.  **객체지향 방식**: 데이터와 그 데이터를 처리하는 로직(행위)이 하나의 객체 안에 캡슐화되어 있는 구조입니다. 객체 스스로가 자신의 상태를 변경하고 비즈니스 로직을 수행합니다.

이를 통해 "객체에게 메시지를 보내 일을 시키는" 객체지향적인 코드의 장점을 명확히 이해할 수 있습니다.
